# agentic-forecasting-tasks

ALE Tasks for live forecasting by general agents. Each forecasting target is one folder,
`tasks/live/<target>/`; contributing a target is a pull request that adds that folder and
nothing else. The pipeline that runs them, scores them and publishes the results is
[agentic-forecasting](https://github.com/rowingchenn/agentic-forecasting).

```text
tasks/
├── live/<target>/        written by the target's author; the same every day
└── mock/<target>/<d>/    generated by the pipeline after run day d; never edited by hand
```

All Tasks follow the [ALE Task format](https://github.com/AgentsLastExam/ale/blob/main/docs/specs/task-authoring.md)
(`core/v1`). Git holds their text; their `*/assets/` folders are gitignored and live in the
private Hugging Face dataset `<ALE_ASSETS_NAMESPACE>/agentic-forecasting-tasks`, synced
with `ale assets push` and `ale assets pull`.

## The live Task

An agent in the live Task receives the instruction, the day's schedule and the open
internet, and no data. It forecasts from whatever it finds, and saves the external
materials it used.

| File | Content |
|---|---|
| `task.yaml` | the Task (open network, no sudo, 90 minutes) and the target, see below |
| `instruction.md` | what to forecast, with the settlement definition precise enough to reproduce independently; the output format |
| `setup/fetch.py` | where the target's numbers come from; the pipeline runs it on the host, never in an episode |
| `setup/run.sh` | writes `/home/user/input/task.json` (run date, target dates, cutoff, quantile levels) from the clock and `params`, then makes its stage directory root-only so the agent cannot read `fetch.py` |
| `verify/` | checks that the submission is well-formed; accuracy is scored after the real values are published |
| `oracle/` | a well-formed submission for `ale validate` |
| `image/` | the sandbox: an ALE base image plus the libraries an agent is likely to want |

`task.yaml` defines the target as the tuple (y, Δ, H, X, B) of the research draft. ALE
rejects unknown top-level fields, so the target lives in `params` and
`extras.agentic-forecasting`:

| Field | Meaning |
|---|---|
| `params.environment_note`, `params.materials_note` | the only instruction text that differs between the live Task and its mock replays (no data provided, what to save); the pipeline sets the mock versions: network cut, forecast from the archive as of the run date, nothing to save |
| `params.timezone`, `params.cutoff` | submissions are due at `cutoff` local time on the run date |
| `params.horizons` | target dates as days after the run date |
| `params.quantile_levels` | the quantiles every forecast submits |
| `extras…title`, `domain`, `region`, `unit`, `tradable`, `summary` | shown on the website |
| `extras…y` | the series, its source and how it is settled (first published value) |
| `extras…schedule.snapshot` | when a run day starts, in `params.timezone` |
| `extras…schedule.every_days`, `first_run` | a run day every `every_days` days from `first_run`; truth is recorded daily regardless |
| `extras…x` | X_d: the structured input the TSFMs receive, its column groups, sources and history start |
| `extras…baseline` | B: `system` id, `label`, the official or expert forecast and how it is read |

`params` must all appear in `instruction.md` (ALE lint enforces it), which also keeps the
agent's instruction in step with the schedule.

### fetch.py

`fetch.py` uses only the standard library and pandas, and reads credentials from
environment variables that the pipeline loads from its `.env`. It defines three functions;
`spec` is the target definition above, with `params` merged in (`horizons`, `quantiles`,
`schedule.timezone`, `schedule.cutoff`).

- `snapshot(run_date, spec)` returns X_d as published at call time, a dict with:
  - `series`: a daily `DataFrame` indexed by date from `x.history_start` to the last
    target date, with a `target` column empty after the last complete day and covariate
    columns known through the forecast window;
  - `last_observed`: the last date with a target value;
  - `raw`: `{file name: DataFrame}` of the finer-grained data `series` was derived from;
  - `sources`: where each part came from; `covariate_notes`: what each column means.
- `truth(today, spec)` returns a date-indexed `Series` of every value published so far.
- `baseline(run_date, spec)` returns `{"source": {...}, "forecasts": [{"target_date":
  ..., "point": ...}]}` (or `"quantiles"` instead of `"point"`) for the version published
  before the cutoff.

The pipeline writes the files (`series.csv`, `raw/`, `task.json`, `MANIFEST.json` with
SHA-256 hashes) and refuses to build X_d for any day but today, so no value published
later can enter it.

## Mock Tasks

After run day d, the pipeline turns the live Task into `tasks/mock/<target>/<d>/`, the
offline replay of that day (`af/mock.py` in the pipeline repository):

- network blocked, and hosted web search disabled through the agents' managed settings,
  since it runs at the model provider outside the sandbox network;
- `setup/assets/task.json`: the schedule the live agents saw;
- `setup/assets/archive/<system>/`: the files each live agent saved with a web source,
  with their `index.jsonl`, installed read-only at `/home/user/input/archive/`;
- `oracle/assets/x/`: X_d. ALE uploads `oracle/` only for oracle episodes, so the
  reference solution (a weekly seasonal naive forecast) uses it and no agent sees it.

Every mock Task is a self-contained offline benchmark item:

```bash
ale assets pull tasks/mock/ercot_peak_load/2026-10-22
ale validate tasks/mock/ercot_peak_load/2026-10-22
ale run tasks/mock/ercot_peak_load/2026-10-22 --config <agent>.toml
```

## Targets

| Target | y | Run days | Horizons | Baseline B |
|---|---|---|---|---|
| `ercot_peak_load` | ERCOT daily system peak load (MW) | every 2 days, cutoff 10:00 CT | 1–7 days | ERCOT seven-day load forecast |

## Adding a target

1. Copy `tasks/live/ercot_peak_load` to `tasks/live/<target>`. Keep the Task name
   `<target with dashes>-live`.
2. Rewrite `task.yaml`, `instruction.md` and `setup/fetch.py`; add libraries to `image/`
   if the target needs them. `setup/run.sh`, `verify/` and `oracle/` work for any target.
3. Check it from the pipeline repository, next to this one:

   ```bash
   uv run python -m af snapshot <target>         # X_d of today, into tasks/mock/<target>/<today>/
   uv run python -m af truth <target>
   uv run python -m af baseline <target> <today>
   scripts/ale validate ../agentic-forecasting-tasks/tasks/live/<target>
   ```

4. Open a pull request with `tasks/live/<target>/` only. The maintainer adds the
   credentials of its data sources to the pipeline's `.env` and enables its timer.

`just lint` checks every Task with the engine of the sibling pipeline repository.
